Catalogue integrity audit
Generated: 2026-07-27 (Track A session)

METHOD
1. Loaded world/assets/catalogue.json (1903 variant entries across 9 sets).
2. For every variant, checked its `source` (3DResources/...) resolves on disk.
3. For every variant carrying a `served` field (i.e. every USED entry's copied
   file), checked `world/<served>` resolves on disk.
4. Separately, for every set under 3DResources/, walked every .fbx and
   checked for a same-directory, same-basename .glb or .gltf sibling — this
   is what the cataloguer itself requires (tools/catalogue-assets.mjs walks
   3DResources/ recursively and only picks up .glb/.gltf files; it never
   reads .fbx directly).

CONCLUSION
The specific failure mode described in the session brief — an FBX->GLB batch
silently dropping files, producing catalogue entries with a `served` path
that doesn't exist on disk — does not reproduce against the current state of
this repo. Every family in BIGNature (including Grass, Grass_Short, Plant,
Cactus, Corn, Wheat, Flowers, Lilypad, TreeStump, WoodLog — none of which
are in the current USED list) already has a complete, matching set of
converted .glb files sitting in 3DResources/BIGNature/. Nothing was ever
lost at the conversion layer for the sets this game currently draws from.

If grass/shrubbery previously failed to render in-game, the most likely
explanation given this evidence is a runtime or recipe-level gap, not a
missing file: see world/zones/grassland/catalogue-flora.js and
world/zones/lagoon/catalogue-flora.js's un-caught promise rejection on a
per-group GLTFLoader failure (a single 404 or parse error aborts every
group processed after it in the same await loop, since nothing there was
wrapped in try/catch) — hardened this session regardless of whether it's
currently triggered, since it's the exact "silent, cascading" shape the
brief is worried about. See PROJECT-STATE.md for detail.

Three-layer hardening applied this session so this class of bug becomes
structurally impossible even if a future asset drop reintroduces a real
conversion gap:
  1. tools/convert-fbx.mjs (new) — per-file exit-code checked FBX->GLB
     conversion with a PASS/FAIL manifest; non-zero process exit on any
     failure. No such reusable/auditable script existed before this session.
  2. tools/catalogue-assets.mjs — now checks the source file exists before
     copyFileSync; a missing source is skipped (no phantom `served` entry
     written) and reported in a loud end-of-run summary; non-zero exit if
     anything was skipped.
  3. world/core/asset-diagnostics.js (new) + both catalogue-flora.js modules
     — a GLTFLoader failure for one group no longer aborts the whole
     placement pass; it's caught per-iteration, console.error'd with the
     exact URL and the family/recipe that referenced it, and surfaced via an
     on-screen "missing assets: N" badge.
